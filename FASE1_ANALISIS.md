##  2. Análisis de repositorios destacados

### 2.1. Información y metadatos

- Tienen una descripción corta y clara sobre el propósito del proyecto.
- Utilizan **Topics**, que son etiquetas para identificar las tecnologías o temas relacionados con el proyecto (por ejemplo: `javascript`, `react`, `open-source`, `hacktoberfest`).
- Incluyen el enlace a una demostración funcional (*Demo*) en la sección **About** del repositorio.

### 2.2. Calidad del archivo `README.md`

- **Propósito claro:** Explican desde las primeras líneas para qué sirve el proyecto.
- **Secciones organizadas:** Incluyen capturas de pantalla o GIFs, tecnologías utilizadas, requisitos previos, pasos de instalación y guía de uso.
- **Contribuciones y licencia:** Cuentan con secciones que explican cómo otras personas pueden colaborar y bajo qué licencia se comparte el proyecto.

### 2.3. Archivos y forma de trabajo

- Incluyen archivos como `LICENSE` (por ejemplo, licencia MIT) y `.gitignore`, configurados según las necesidades del proyecto.
- Mantienen un historial de cambios ordenado mediante convenciones como **Conventional Commits**, utilizando mensajes como `feat:`, `fix:` y `docs:`.
- Utilizan **Branches** para desarrollar nuevas funciones sin modificar directamente la rama principal.
- Trabajan con **Pull Requests** para revisar los cambios antes de integrarlos a `main`.
- Utilizan **Issues** para registrar errores, problemas o posibles mejoras.

##  3. Requisitos del perfil / portafolio

### 3.1. Requisitos funcionales

*Son las características y elementos que debe incluir el portafolio.*

| **Código** | **Requisito** | **Descripción** |
|---|---|---|
| **RF-01** | Presentación | Debe tener una sección de «Sobre mí» donde aparezcan el nombre, la profesión o rol principal (por ejemplo, Desarrollador Web o de Software) y una pequeña descripción personal. |
| **RF-02** | Habilidades técnicas | Debe mostrar los lenguajes de programación, tecnologías y herramientas que conoce, utilizando íconos o insignias para identificarlos fácilmente. |
| **RF-03** | Proyecto destacado | Debe mostrar al menos 1 proyecto importante. Debe incluir nombre, breve descripción, tecnologías utilizadas, enlace al repositorio de GitHub y enlace para ver el proyecto funcionando. |
| **RF-04** | Contacto | Debe incluir enlaces fáciles de encontrar para contactar al desarrollador, como su correo electrónico, LinkedIn y GitHub. |
| **RF-05** | Navegación | Debe contar con un menú sencillo que permita moverse fácilmente entre las diferentes secciones del perfil, como Sobre mí, Proyectos, Habilidades y Contacto. |

### 3.2. Requisitos no funcionales

*Son las características que determinan cómo debe funcionar y verse el portafolio.*

| **Código** | **Requisito** | **Descripción** |
|---|---|---|
| **RNF-01** | Adaptación a dispositivos | El portafolio debe verse correctamente en celulares, tablets y computadoras. |
| **RNF-02** | Accesibilidad | Los textos deben tener buen contraste con el fondo y las imágenes deben incluir una descripción (`alt`) para facilitar su comprensión. |
| **RNF-03** | Organización del código | Los archivos del proyecto deben estar ordenados en carpetas, por ejemplo, `/assets`, `/css` y `/js`, y el sitio debe estar publicado en GitHub Pages. |
| **RNF-04** | Velocidad de carga | La página debe cargar rápidamente, utilizando imágenes optimizadas y recursos que no hagan más lenta su apertura. |
